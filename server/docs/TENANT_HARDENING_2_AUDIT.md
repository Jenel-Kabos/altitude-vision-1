# TENANT-HARDENING-2 — Audit initial des frontières indirectes

Audit réalisé avant toute modification runtime. Sources relues : `TENANT_CERT_2_AUDIT.md`, `TENANT_CERT_2_REPORT.md`, routes, contrôleurs, services, modèles, serveur Socket.IO, clients Web et Mobile.

## Limitations reprises de TENANT-CERT-2

Les limitations explicites sont : Reporting/ERP global sans scope, Socket.IO non certifié, fichiers/Cloudinary non audités, contenu des exports non vérifié, webhooks non ré-attaqués, search transversal partiel, mass-assignment non exhaustif, liste Gestion locative non filtrée et frontières indirectes cron/email/cache non prouvées. Le défaut Playwright mobile a depuis été fermé par UI-UX-CERT-1 et ne constitue plus une limitation.

## Décision d’audit

Le code runtime ne peut pas être déclaré certifié en l’état : Reporting/ERP par défaut, Socket staff inbox, export contacts, documents GL staff, cache Mobile et liste GL présentent des chemins exploitables plausibles. La phase suivante doit d’abord matérialiser ces chemins par contrôles positifs et attaques rouges. Les URLs Cloudinary publiques constituent par ailleurs une limitation de stockage réelle : une autorisation HTTP ne peut révoquer une URL publique déjà connue.
