## Limite documentée (non un échec de test, une limite de conception assumée)

Le ledger (`FinancialLedgerEntry`) écrit par la réconciliation déclenchée automatiquement (callback) porte `actorType: 'user'` avec `actorId: null` — la fonction canonique `confirmHotelPaymentCore`/`failHotelPaymentCore` (réutilisée sans modification, mandat §30) ne distingue pas un acteur système d'un acteur humain. Ce n'est pas une vulnérabilité (l'attribution reste traçable via `businessOperationKey` et l'horodatage), mais une imprécision d'étiquetage documentée comme dette (§16 du rapport).
